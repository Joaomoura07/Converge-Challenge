1Regras que mudam o plano

⛔ Nada de código do projeto antes de sábado, 10h O guia é explícito: "Ninguém escreve código do projeto antes deste horário", e os organizadores podem pedir o histórico de commits. O material de apresentação também só vale durante o evento.
Por isso, o "mão na massa da noite" (escrever o system prompt e codar as tools na sexta) saiu do plano. Na sexta, decidimos o quê e desenhamos no papel. No sábado às 10h, codamos.
✅ Permitido antesPesquisa, conversar com potenciais clientes, modelagem de negócio, arquitetura no papel, preparar o ambiente (contas, chaves, Docker, repositório-base), especificar casos de teste em texto.
❌ Só a partir de sábado 10hCódigo do produto (tools do domínio, prompt do domínio, mocks, dados sintéticos em código), build, slides e vídeo.
Correções do plano anterior
  • Não comentem o @observe nem a linha do trace_url. O erro 500 já foi corrigido no repositório: sem chave válida do Langfuse, o tracing desliga sozinho. Basta dar git pull.
  • Não precisa de pip install langfuse. Ele já está no requirements.txt. "Módulo não encontrado" significa que o ambiente virtual não foi ativado: .venv\Scripts\activate.
  • O evento é no Porto Digital (Bairro do Recife), não no CIn-UFPE.
  • O código de crédito da Featherless vence em 8/11 e tem limite de resgates: quem ainda não resgatou, resgate hoje.
Pergunte no grupo do WhatsApp Nosso repositório-base (infraestrutura genérica, sem lógica de produto) foi criado antes do evento. Isso se enquadra em "preparação de ambiente", mas vale confirmar com a organização. Se disserem que não pode, recriamos o repositório no sábado a partir desses arquivos.

3Sexta à noite (hotel)

Fase 1 · Fechar o ambiente (≈ 45 min). Todos, cada um na sua máquina

  • git pull e ativar o venv; pip install -r requirements.txt
  • Cada pessoa com a própria FEATHERLESS_API_KEY no .env (créditos resgatados)
  • Langfuse: criar o projeto, gerar as chaves reais (cerca de 40 caracteres) e conferir se a região bate com o LANGFUSE_HOST. Compartilhar o projeto com o time
  • Supabase: no SQL Editor, rodar sql/001_agent_runs.sql
  • python -m scripts.check_setup com todos os itens [OK]
  • docker compose --profile n8n up -d --build → importar, publicar e reiniciar a ponte (ver Documento 2) → testar o curl no webhook
  • Instalar o túnel (ngrok com authtoken, ou cloudflared) e testar localhost:8000/docs pela URL pública, no celular e no 4G
  • Escolher onde fazer o deploy (serviço que rode o Dockerfile) e criar a conta. Subir a base atual como teste é preparação de ambiente
  • Baixar tudo que for pesado no hotel: a rede do evento é compartilhada
  • Lembrete no celular: cancelar o plano da Featherless antes da primeira cobrança

Pronto quando: o webhook do n8n devolve uma resposta do agente e um trace aparece no Langfuse.

Fase 2 · Ideação e arquitetura no papel (≈ 1h30). Notebooks fechados

  1. Escolher a dor com o Documento 1 (filtro de 6 perguntas + matriz). Recomendação: Guardião de Férias e Prazos CLT.
  2. Preencher o canvas de uma página (abaixo).
  3. Desenhar o fluxo ReAct do caminho feliz e da exceção estrela, passo a passo: Pensa → Ferramenta → Observa → …
  4. Listar as ferramentas: nome, o que recebe, o que devolve, se escreve dados (aí precisa de dry_run). Só no papel.
  5. Escrever 6 a 8 casos de teste em português (entrada → resultado esperado), incluindo exceções. Viram os evals no sábado.
  6. Especificar os dados sintéticos: quantos colaboradores, quais campos, quais "pegadinhas" plantar (férias vencendo, conflito de datas).

Prêmio AWS: deixar resolvido no sábado à noite

Os créditos (US$ 5–10 mil) só são liberados com: (1) site no ar em domínio próprio, (2) e-mail corporativo no mesmo domínio (Gmail, Outlook e .edu são recusados), (3) conta AWS ativa. Registrar um .com.br leva minutos, e o registro não é coberto pelos créditos. Uma landing de uma página basta.
